# DESIGN_REVIEW_PROTOCOL.md

Version: 1.0
Status: Mandatory

This document is the final quality gate for every interface generated by ATHR.
Nothing is considered complete until it passes this review.
The goal is not visual perfection.
The goal is clarity.

*   **Intent**: Create a strict quality standard that automatically rejects UI that does not align with the core UX priorities.
*   **Implementation**: Verify all UI code, states, and copy against this list. AGY must self-assess prior to finalization.
*   **Anti-patterns**: Merging interfaces based on "looks good" without validating cognitive load, mobile zone comfort, and loading transition times.
*   **Acceptance Criteria**: The screen satisfies 100% of the checklist items and triggers zero Automatic Rejection Conditions.

---

# Review Philosophy

Every review asks one question:
"Does this make the user's life easier?"
Everything else is secondary.
Never review aesthetics first.
Always review understanding first.

---

# Review Order

Every interface must be reviewed in this order.
1. Psychology
2. Content
3. Information Architecture
4. Layout
5. Typography
6. Visual Hierarchy
7. Interaction
8. Motion
9. Accessibility
10. Performance
11. Implementation
Never review out of order.

---

# PASS CONDITIONS

An interface passes only when:
- Users immediately understand where they are.
- Users immediately understand what happened.
- Users immediately understand what to do next.
- No unnecessary thinking exists.
- No unnecessary visual noise exists.
- No unnecessary interaction exists.

---

# PSYCHOLOGY REVIEW

Ask:
- Can the interface be understood within three seconds?
- Does the screen reduce cognitive load?
- Is attention directed naturally?
- Are users making fewer decisions?
- Is progressive disclosure applied?
- Does every visible element deserve attention?
- Is there any unnecessary information?
- Is trust increased?
- Does the interface reduce anxiety?
- Does the interface feel predictable?

Fail immediately if any answer is no.

---

# CONTENT REVIEW

- Is every headline meaningful?
- Can paragraphs become shorter?
- Can information be scanned?
- Are important ideas visible?
- Can users understand without reading everything?
- Is any sentence decorative?
Remove anything unnecessary.

---

# INFORMATION ARCHITECTURE

- Can users predict where everything lives?
- Are related actions grouped together?
- Are dangerous actions isolated?
- Can users always return?
- Does navigation explain itself?
- Is hierarchy obvious?

---

# LAYOUT REVIEW

- Is the layout breathable?
- Does every section have enough space?
- Are elements aligned?
- Is whitespace intentional?
- Are sections visually balanced?
- Does the eye naturally know where to look first?
- Does the page feel calm?

---

# TYPOGRAPHY REVIEW

- Is typography doing most of the work?
- Are font sizes consistent?
- Is line height comfortable?
- Is line length comfortable?
- Does Arabic feel professionally typeset?
- Does English match Arabic visually?
- Are headings descriptive?
- Can bold text be reduced?
- Is color replacing typography?
If yes, fix typography first.

---

# COLOR REVIEW

- Does every color communicate meaning?
- Are semantic colors respected?
- Is contrast sufficient?
- Can color usage be reduced?
- Does any color exist only because it looks nice?
Remove it.

---

# VISUAL HIERARCHY

Can users identify:
- Primary
- Secondary
- Tertiary
Information instantly?
If hierarchy depends on color, the hierarchy is wrong.

---

# ICON REVIEW

- Are icons necessary?
- Do icons clarify meaning?
- Are icons decorative?
If decorative, remove them.
- Are all icons from the same family?
- Consistent stroke?
- Optically aligned?
- Colored highlights used appropriately to denote categories?

---

# IMAGE REVIEW

- Does every image communicate information?
- Can screenshots replace illustrations?
- Can real work replace stock photography?
- Does imagery build trust?
If not, remove it.

---

# SURFACE REVIEW

One surface. One purpose.
Ask:
- Does this surface contain multiple unrelated responsibilities?
- Is there a card inside another card?
- Are borders unnecessary?
- Could spacing replace borders?
- Could hierarchy replace containers?
Reduce surfaces whenever possible.

---

# COMPONENT REVIEW

- Does every component behave predictably?
- Does every component follow the system?
- Has any page invented its own component?
If yes, replace it.

---

# BUTTON REVIEW

- Is there exactly one primary action?
- Can secondary buttons become ghost buttons?
- Can tertiary buttons become text buttons?
- Are button labels action-oriented?
- Is there visual competition?
Reduce it.

---

# INPUT REVIEW

- Are labels persistent?
- Is validation helpful?
- Can typing effort be reduced?
- Are touch targets large enough?
- Is keyboard behavior correct?

---

# NAVIGATION REVIEW

- Can navigation become simpler?
- Can destinations become fewer?
- Does navigation disappear into habit?
- Can users always recover?

---

# MOBILE REVIEW

Review first on mobile. Always.
Ask:
- Can everything be reached comfortably?
- Is the thumb zone respected?
- Does scrolling feel natural?
- Are gestures optional?
- Does keyboard hide anything?
- Does the page feel native?
Desktop is reviewed only after mobile passes.

---

# RESPONSIVE REVIEW

Nothing should feel redesigned.
Desktop expands. It never changes philosophy.

---

# MOTION REVIEW

Motion must answer: Why?
Ask:
- Does this animation communicate?
- Does it preserve context?
- Can morphing replace replacement?
- Can layout animation replace opacity?
- Is AnimatePresence using mode="wait"?
- Are two major animations occurring simultaneously?
- Can animation duration be shorter?
- Can animation be removed?
If removing motion improves UX, remove it.

---

# MORPHING REVIEW

Whenever two objects represent the same thing, they should morph.
Never disappear. Never teleport. Never recreate.

---

# LOADING REVIEW

Is loading necessary?
- If loading is under 150ms: show nothing.
- If between 150–800ms: prefer skeleton.
- If longer: show meaningful progress.
Never fake progress. Never block users unnecessarily. Never show huge spinners.

---

# EMPTY STATE REVIEW

- Does empty state teach?
- Does it explain?
- Does it suggest?
- Does it encourage action?

---

# ERROR REVIEW

- Does the error explain?
- Does it reduce anxiety?
- Does it offer recovery?
- Does it avoid blame?

---

# FEEDBACK REVIEW

Every interaction should answer:
- Did it work?
- What changed?
- What happens next?
Nothing should feel silent.

---

# ACCESSIBILITY REVIEW

- Keyboard navigation.
- Focus visibility.
- Contrast.
- Touch targets.
- Reduced motion.
- RTL support.
- Screen reader compatibility.
Every screen must pass.

---

# PERFORMANCE REVIEW

- Is every animation GPU-friendly?
- Can layout calculations be reduced?
- Are images optimized?
- Is lazy loading applied?
- Can unnecessary JavaScript be removed?
- Does scrolling remain smooth?
Target: 60 FPS Always.

---

# AI EXPERIENCE REVIEW

- Does AI feel native?
- Does AI explain itself?
- Does AI avoid fake confidence?
- Does AI stream naturally?
- Does AI reduce work?
- Does AI remember context?
- Does AI feel like part of ATHR? Not another widget.

---

# IMPLEMENTATION REVIEW

- Does this reuse components?
- Does this reuse tokens?
- Has anything been hardcoded?
- Has the design system been bypassed?
If yes, reject implementation.

---

# FINAL QUESTIONS

Before shipping ask:
- Would removing this improve clarity?
- Would removing this improve calmness?
- Would removing this reduce cognitive load?
If yes, remove it.

---

# DEFINITION OF EXCELLENT

An excellent interface is one that users stop noticing.
Attention stays on their goal. Never on the interface.

---

# AUTOMATIC REJECTION CONDITIONS

Reject immediately if any of the following exist:
- Glassmorphism.
- Card inside card.
- Decorative shadows.
- Bounce animation.
- Pop animation.
- Random slide directions.
- Multiple icon families.
- Inconsistent spacing.
- More than one primary CTA.
- Decorative illustrations.
- Decorative animations.
- Typography used incorrectly.
- Desktop-first thinking.
- Missing loading state.
- Missing empty state.
- Missing error state.
- Missing success feedback.
- Missing accessibility.

---

# Definition of Done

A screen is complete only when:
✓ Psychology passes.
✓ UX passes.
✓ Content passes.
✓ Mobile passes.
✓ Motion passes.
✓ Components follow the system.
✓ Tokens are respected.
✓ Accessibility passes.
✓ Performance passes.
✓ AI behavior follows the constitution.
✓ The interface feels calm.
✓ The interface feels invisible.

If one item fails, the feature is not complete.
